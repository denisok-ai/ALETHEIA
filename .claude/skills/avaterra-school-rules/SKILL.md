# Правила школы Аватэрра (чек-лист)

Этот скил не пишет тексты. Он задаёт проверку, которую проходит каждый текст из других скилов `avaterra-*`.
Правила живут в коде. Если чек-лист расходится с кодом, верить коду и поправить этот файл.

## Источники правил

- `content/knowledge/avaterra.yaml`: `prohibited_phrases`, `safe_replacements`, `disclaimer`, `editor_checklist`, `products.telo_znaet_vse`, `pricing_policy`.
- `lib/content/quality-gates.ts`: автоматические блокировки (`scanPublishBlockers`, `normalizePostLexicon`, `evaluateText`).
- `lib/social/captions.ts`: `buildCaption` возвращает `warnings` для подписи соцсети (правила, «не» в заголовке, длина, запрещённые фразы).
- `lib/social/refs.ts`: формат меток `?ref=`.

## Приоритет

1. Правила школы (этот файл, `avaterra.yaml`, quality gates) важнее задачи. Если задача требует нарушить правило, не выполнять и сказать об этом.
2. Конкретное требование задачи важнее минимума скила (например, число вариантов заголовков).
3. Если скил расходится с кодом, верить коду и сообщить об расхождении.

## Блокировки (quality gate, пост не встанет в очередь)

| Что нельзя | Чем заменить |
|---|---|
| «калибр…» (калибровка, калибровать, калиброванный) | «замер через баланс тела», «сверка баланса», «сверить ответ с балансом» |
| «метод» и формы слова (метода, методом, методы) | «подход школы», «практика», «мышечное тестирование» |
| «FAQ» (акроним) | «раздел «Описание»» или «Вопросы и ответы» |
| «Тело не врёт» (старое название курса) | «Тело знает всё» |
| латиница «Avaterra» | «Аватэрра» (латиница только в адресах сайта) |
| «мы вылечим», «вылечим вас», «боль уйдёт навсегда» | «помогает работать со стрессом» |
| «это точно из-за психосоматики» | «иногда причина может быть связана с прошлым опытом» |
| «можно не ходить к врачу» | дисклеймер (см. ниже) |
| «школа Аватэрра гарантирует результат», «гарантированный результат», «100% результат», «точно поможет всем» | описать процесс без обещаний |
| «тело всегда даст идеальный ответ» (и любые «всегда / без ошибок» про тело) | описать как наблюдение: «тело подаёт сигнал, его стоит проверить» |
| «у вас травма в ... возрасте» | не писать |

Полный список регулярных выражений: `content/knowledge/avaterra.yaml`, раздел `prohibited_phrases`. Замены: раздел `safe_replacements`.

Замены `normalizePostLexicon` («калибровка» → «замер через баланс тела», «калибровать ответ» → «сверить ответ с балансом») делаются в подписи молча, без предупреждения. Поэтому проверять исходный текст автора, а не готовую подпись.

## Правила, которые проверяются вручную

1. **Заголовки и названия без частицы «не»** (правило Татьяны). «Тело знает всё», а не «Тело не врёт». Внутри текста тоже утвердительно: «тело отвечает честно», «тело знает». Проверка в коде: `titleProblems` в `lib/social/captions.ts`.
2. **Имя школы кириллицей:** «Аватэрра».
3. **Тон:** тёплый, спокойный, экспертный, на «вы». Без давления, запугивания и «срочно, пока не поздно». Без избыточной эзотерики (`tov_donts` в yaml).
4. **Медицина и психика.** Нет диагнозов, прямых медицинских рекомендаций, обещаний результата. Если в теме или тексте есть слово из `disclaimer.triggers` (боль, травма, тревог, паник, депресс, психосомат, симптом, болезн, температур) в любой форме (боли, болью, тревога, паника), добавить `disclaimer.text` дословно или отдельным абзацем. Совпадение по слову, не по подстроке: «больше» и «большой» триггер не запускают (`matchesDisclaimerTrigger`, `lib/content/quality-gates.ts`). Очередь дисклеймер сама не проверяет, проверять вручную.
5. **Цены.** Публичная цена практикума «Тело знает всё» (5 000 ₽) называется только там, где это разрешено yaml (`pricing_policy`): в постах и CTA о практикуме. Цены других продуктов (Пробуждение, Мастер, личная работа) не называть: вести на страницу тарифа.
6. **Продажа практикума.** «Тело знает всё» продаётся с 13.10.2026 (онлайн-оплата ЮKassa, страница `/course/navyki-myshechnogo-testirovaniya`). Призыв купить и цена 5 000 ₽ допустимы: цена публичная по `pricing_policy`. Цены других продуктов не называть.
7. **Формулировки про практикум:** «самостоятельно, в своём темпе, без живых занятий». Нельзя писать про кураторов, проверку домашних заданий, живой разбор, сертификат (в yaml сертификат не выдаётся).
8. **Платные протоколы не раскрывать** в открытом канале: шаги теста, последовательность, точные техники из курса (`theme_bank`, пост «Почему важно не раскрывать платные протоколы»). Статья блога `/blog/myshechnoe-testirovanie-na-sebe` описывает три способа самотеста: ссылаться на неё в открытом канале — решение владельца, до него не ставить.
9. **Факты только из базы.** Опыт и цифры Татьяны берутся из `author.facts` в yaml. Не выдумывать даты старта, отзывы, цифры, количество учеников.
10. **Один главный тезис** в посте (`editor_checklist`).
11. **Ссылки.** Ссылка на сайт с меткой `?ref=` по площадке: `tg-NN` (Telegram), `mx-NN` (MAX), `vk-NN` (VK), `dz-NN` (Дзен). Префиксы в `REF_PREFIX_TO_NETWORK` (`lib/social/refs.ts`). Instagram не нажимает ссылки в подписи: писать «Ссылка в профиле».
12. **Лимиты.** Telegram: 1024 знака к видео, 4096 к тексту без медиа. MAX: 4000 (`lib/social/telegram-caption.ts`). VK: 600 (`VK_CAPTION_MAX`, `lib/social/captions.ts`). Дзен и прочие сети: 2200 (`CAPTION_LIMIT_DEFAULT`).

## Порядок проверки

1. Пройти таблицу блокировок и заменить найденное.
2. Пройти пункты 1–12. Каждый результат записать как «да / нет / не применимо».
3. Если текст пойдёт в очередь: `npx tsx scripts/social-enqueue.ts queue.json --dry`. Он выведет предупреждения `buildCaption`. Без предупреждений запись не произойдёт. Команда требует доступ к локальной БД.
   `--dry` не проверяет: окна длины по типу поста, латиницу, дисклеймер, CTA и рубрику. Эти пункты проверять вручную по списку выше.
4. Вернуть владельцу: текст, список замен, предупреждения. Публиковать самому нельзя: публикация только через очередь и по решению владельца.

## Что не делаем

- Не публикуем и не отправляем ничего в соцсети из этого скила.
- Не пишем в репозиторий платный контент, ПДн, расшифровки. Такие материалы — в `~/projects/AVATERRA-private`.
- Не меняем `lib/` и `content/knowledge/avaterra.yaml` без отдельной задачи. Чек-лист читает правила, а не переписывает их.
