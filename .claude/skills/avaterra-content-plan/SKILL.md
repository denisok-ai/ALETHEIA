# Контент-план на 2–4 недели

Собираем план из существующих рубрик, типов постов и тем. Выход — один файл очереди для `scripts/social-enqueue.ts`: видео с `file` и текстовые посты без него.

## Входные данные

- период: 2 или 4 недели, с какой даты (по МСК);
- площадки: `telegram`, `max` (очередь), `vk`, `dzen` (план и ручная публикация);
- материалы: готовые видеофайлы в каталоге соцсетей (`getMediaDir` в `lib/social/scheduler.ts`) и их имена. Видео без файла в очередь не ставится;
- темы недели (необязательно): список запросов с показами на 6–20 месте из недельного дайджеста SEO (раздел «Темы недели», `lib/seo/weekly-digest.ts`) или страница `/portal/admin/seo`.

## Ритм

- **Telegram и MAX:** один пост в день на сеть. Планировщик публикует не больше одной публикации в сеть за день по Москве (`SCHEDULER_LIMITS.perNetworkPerDay`), поэтому план не ставит два поста в один день.
- **Типы по дням недели** (из `post_types.weekday`): понедельник — `educational`, вторник — `pain`, среда — `practice`, четверг — `author`, пятница — `faq`, суббота — `course`, воскресенье — `reflection`.
- **VK Клипы:** 3–4 ролика в неделю (план из `docs/research/audience-platforms-2026-10.md`). Текст к клипу — по `post_type` дня.
- **Дзен:** статьи блога по одной в неделю (кросспост с канонической ссылкой на сайт).
- Практикум в `course`-дни: только если он на витрине с онлайн-оплатой. Иначе вместо `course` ставить `faq` или `reflection`, а в поле `note` указать причину.

## Процесс

1. Прочитать `content/knowledge/avaterra.yaml`: `rubrics`, `post_types`, `theme_bank`, `audiences`.
2. Прочитать темы недели (если есть). Для каждого запроса найти ближайшую тему в `theme_bank` или предложить новую, по которой есть страница сайта (статья блога или глоссарий). Запрос, по которому уже есть сильная страница, не превращать в новый пост: такой пост конкурирует со страницей.
3. Распределить по дням: тип дня задаёт `post_type`, тема — из `theme_bank` с этим типом. Аудитория — `default_audience` типа.
4. Для каждой записи назначить метку `ref` по префиксу сети и номеру: `tg-01`, `tg-02`… для Telegram, `mx-01`… для MAX. Номер растёт по порядку материалов. Метки не повторяются.
5. Все записи собрать в один JSON (формат ниже): видео — с `file`, текстовые посты — без `file`, с `body`.
6. Проверить каждый текст по `avaterra-school-rules`. Подписи и лимиты проверит `scripts/social-enqueue.ts --dry`.

## Формат выхода

Файл `queue.json` (сохранить в папку, которую укажет владелец, не в репозиторий):

```json
[
  {
    "file": "2026-10-19-pochemu-drozhat-ruki.mp4",
    "title": "Почему дрожат руки",
    "body": "Короткий текст поста.",
    "ref": "tg-01",
    "scheduledAt": "2026-10-19 10:00"
  },
  {
    "title": "Вопрос недели",
    "body": "Текст текстового поста, без ролика. Ссылка на практикум добавится сама.",
    "ref": "tg-02",
    "scheduledAt": "2026-10-20 10:00"
  }
]
```

Правила формата (`lib/social/queue-input.ts`):
- `scheduledAt` без смещения — московское время, формат `ГГГГ-ММ-ДД ЧЧ:ММ`;
- `ref` — только для сети очереди (`tg-` для Telegram, `mx-` для `--network=max`);
- `file` — имя файла в каталоге соцсетей. Есть `file` — видео (лимит подписи: 1024 знака в Telegram, 4000 в MAX). Нет `file` — текстовый пост: `body` обязателен, лимит текста 4096 в Telegram, 4000 в MAX;
- `hashtags` — необязательно.

Текстовый пост в очереди записывается как `news` без медиа: планировщик публикует его текстом. В `--dry` он помечен как «текстовый пост, без медиа».

Закончить блоком «Что нужно от владельца»: готовые файлы, решение по курсу, темы, на которые нет страницы сайта.

## Правила

- Не ставить в очередь видео без файла в каталоге и без проверки подписей.
- Не дублировать одну тему два раза за период. Не дублировать тему из `theme_bank` в соседних днях.
- Не назначать метку площадки, которой нет в очереди (сейчас VK и Дзен очередью не публикуются).
- Не добавлять цены в тексты постов. Исключение — `course_body` в `course`-посте (см. `avaterra-school-rules`).
- План — предложение. Владелец утверждает до постановки в очередь.

- `lib/social/scheduler.ts` — ритм «одна публикация в день на сеть».
