# Голос школы: разбор и проверка

Голос школы описан в `content/knowledge/avaterra.yaml` (`brand.tone_of_voice`, `tov_dos`, `tov_donts`, `author.voice_rules`). Этот скил превращает описание в замеры по реальным текстам и помогает держать стиль. Он не копирует чужие тексты и не выдаёт за голос Татьяны то, что она не говорила.

## Входные данные

- 3–5 образцов текста школы: опубликованные статьи блога (`lib/content/kb-seo-articles.ts`), страницы глоссария (`lib/content/glossary.ts`), опубликованные посты владельца, если он их дал;
- `docs/Telegram-Content-Knowledge-Base.md` — только как вспомогательный источник: после чистки 17.10 (слова «метод», «калибровка» и старое название курса заменены). Шаблоны из него сверять с yaml, на образец они не годятся без проверки;
- новый текст для проверки (необязательно);
- что нужно: разбор голоса, проверка текста или переписывание в голос.

Образцы — только тексты школы. Не брать переписку с клиентами, отзывы с именами, расшифровки занятий: это ПДн или платный контент.

## Процесс

1. Прочитать `brand.tone_of_voice` и `tov_dos` / `tov_donts` в yaml.
2. Прочитать 3–5 образцов. Не делать выводов по одному тексту.
3. Замерить:
   - средняя длина предложения (в словах) и разброс;
   - как начинается текст (наблюдение, вопрос, ситуация, утверждение);
   - обращение: «вы» или «мы», доля каждого;
   - частые слова и обороты (например «тело», «реакция», «сверка баланса», «заметить»);
   - как заканчивается текст: вопрос, CTA, наблюдение;
   - чего в образцах нет (отмечать с числом образцов). Например, «ни в одном из 4 текстов нет восклицательных знаков».
4. Разделить выводы на две группы:
   - **явные запреты** (из yaml и правил школы): их не пересматриваем;
   - **наблюдения по образцам** (например, «в 3 из 4 текстов вопрос в конце»): помечать как предварительные, по числу образцов. Отсутствие в малой выборке не равно запрету.
5. Для проверки нового текста: сверить с выводами пункта 3 и с правилами `avaterra-school-rules`. Указать 3–5 конкретных мест с предложением правки. Не переписывать весь текст, если не попросили.
6. Для переписывания в голос: сохранить тезис автора, поменять только тон и ритм. Не добавлять факты.

## Формат выхода

```
ГОЛОС ШКОЛЫ: разбор по <N> образцам (<список источников>)

Явные правила (из yaml): <3–5 пунктов>
Наблюдения по образцам (предварительно):
- <наблюдение> (<k> из <N> образцов)

Проверка текста:
| Место | Что не так | Предложение |
|---|---|---|

Вердикт: соответствует / нужны правки (<N>)
```

## Правила

- Не выдавать себя за Татьяну. Цитаты из её речи — только из материалов владельца, с указанием источника.
- Не менять факты и цифры при переписывании. Опыт автора — только из `author.facts` в yaml.
- Не вводить в тексты латиницу «Avaterra» и слово «метод»; проверять по `avaterra-school-rules`.
- Не сохранять разбор в репозиторий без решения владельца. Если нужен файл, предложить владельцу имя docs/marketing/voice-avaterra.md (без создания) и дождаться ответа.
