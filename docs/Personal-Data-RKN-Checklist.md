# Чеклист: персональные данные, Роскомнадзор, 152-ФЗ (AVATERRA)

Документ для владельца/юриста: сверка с сайтом [avaterra.pro](https://avaterra.pro) и подготовка уведомления об обработке ПДн. Не заменяет юридическую консультацию.

## 1. Реквизиты оператора (обязательно заполнить в `.env`)

Переменные с префиксом `NEXT_PUBLIC_` попадают на страницы `/privacy`, `/pd-consent` и в футер:

| Переменная | Пример |
|------------|--------|
| `NEXT_PUBLIC_PDN_OPERATOR_NAME` | Полное наименование ИП/ООО |
| `NEXT_PUBLIC_PDN_OPERATOR_INN` | ИНН |
| `NEXT_PUBLIC_PDN_OPERATOR_OGRNIP` | ОГРНИП (для ИП) или ОГРН (для ЮЛ) |
| `NEXT_PUBLIC_PDN_OPERATOR_ADDRESS` | Юридический / почтовый адрес |
| `NEXT_PUBLIC_PDN_DPO_EMAIL` | Email для обращений по ПДн |

После заполнения пересоберите приложение (`npm run build`) и выкатите на прод.

## 2. Что сделано в продукте (технически)

- Полная **политика обработки ПДн**: [`/privacy`](../app/privacy/page.tsx).
- Отдельное **согласие**: [`/pd-consent`](../app/pd-consent/page.tsx).
- **Обязательная галочка** на оплату, регистрацию, комментарии к публикациям; сервер отклоняет запрос без `pdConsent: true`.
- **Журнал согласий** в БД: модель `ConsentLog` (регистрация, оплата, комментарий).
- **Cookie-баннер**: необходимые / аналитика.
- **Яндекс.Метрика** загружается только после согласия на аналитику.
- **Google Analytics и Microsoft Clarity** из корневого layout **не подключаются**.

## 3. Уведомление в РКН — сводные поля для подачи

Заполните и используйте на портале РКН / Госуслугах по актуальной форме.

1. **Оператор**: наименование, ИНН, ОГРН(ИП), адрес, контакт для обращений субъектов.
2. **Цели обработки**: заявки, договор, оплата, ЛК, обучение, поддержка, уведомления, безопасность, аналитика (после согласия).
3. **Категории субъектов**: посетители сайта, клиенты, пользователи портала, абоненты рассылок.
4. **Категории ПДн**: ФИО, email, телефон, данные аккаунта, платежи, обращения, технические данные, cookie.
5. **Способы обработки**: с автоматизацией и без (в зависимости от процессов).
6. **Передача третьим лицам**: PayKeeper, почта (Resend/SMTP), хостинг, Telegram, LLM-провайдер при использовании чата.
7. **Трансграничная передача**: зафиксируйте фактическую картину (LLM; иностранная аналитика на сайте отключена по умолчанию).
8. **Меры защиты**: HTTPS, доступы, хэш паролей, резервное копирование и т.д. (внутренний перечень).
9. **Дата начала** обработки на текущем домене / **дата изменения** политики.

## 4. Решения по аналитике

- **Рекомендуемый режим**: только **Яндекс.Метрика** после согласия.
- Включение **Google Analytics / Clarity** потребует отдельного юридического обоснования и доработки политики и, возможно, механизма согласия.

## 5. Рекомендуемые следующие шаги

1. Проставить все `NEXT_PUBLIC_PDN_*` на проде.
2. Подать/актуализировать **уведомление** в РКН.
3. Вести **локальный регламент** (Политика конфиденциальности персонала, доступы, сроки хранения по категориям).
4. При найме сотрудников — **согласия** и локальные акты на обработку ПДн сотрудников (отдельно от сайта).
