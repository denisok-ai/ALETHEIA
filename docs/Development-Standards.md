# Стандарты разработки AVATERRA

Действует с 21.11.2026. Грабли проекта (Prisma, title, IP клиента, robots и т. п.) — в
[CLAUDE.md](../CLAUDE.md), раздел «Грабли»; здесь — как устроен репозиторий и как в нём работать.

## 1. Всё — в одной папке

Всё, что относится к проекту, живёт в `~/projects/AVATERRA` (репозиторий `denisok-ai/ALETHEIA`).
Соседних копий, «временных» папок проекта и файлов на рабочем столе не держим.

| Папка | Что в ней | В git |
|---|---|---|
| `app/` | Маршруты Next.js (App Router): страницы, `api/`, `portal/` | да |
| `components/` | Общие React-компоненты; `components/ui/` — примитивы | да |
| `lib/` | Бизнес-логика и интеграции; страницы и API только вызывают её | да |
| `prisma/` | `schema.prisma`, `migrations/`, `seed` | да (БД `dev.db` — нет) |
| `content/` | Знания школы и бота (`knowledge/avaterra.yaml` — правила текстов) | да |
| `scripts/` | Скрипты эксплуатации, см. [scripts/README.md](../scripts/README.md) | да |
| `tests/` | `unit/` — чистые модули, `db/` — на изолированной SQLite, `e2e/` — Playwright | да |
| `infra/` | systemd-юниты и шаблоны конфигов сервера | да |
| `docs/` | Документация, см. [docs/README.md](README.md); `docs/archive/` — история | да |
| `public/` | Статика сайта (`public/uploads/` — загрузки, вне git) | частично |
| `uploads/` | Приватные вложения приложения (письма, рассылки, сертификаты) | нет |
| `private/` | Платный контент, ПДн, расшифровки, бэкапы, черновики, тяжёлые медиа | **нет** |

**Репозиторий публичный.** Платные материалы, персональные данные, токены, дампы БД — только в `private/`
(в `.gitignore`). Бэкапы БД — `private/archive/db/`, не рядом с `prisma/dev.db`.

## 2. Проверки перед push

```bash
npm run check
```

`check` = `lint` + `typecheck` + `typecheck:scripts` + `test`. Плюс перед push в `main`:

```bash
npm run build
```

Смотрите **код выхода**, а не хвост лога (`npm run build; echo BUILD_EXIT=$?`): `| tail` прячет падение.

CI (`.github/workflows/deploy.yml`) повторяет то же: линтер → типы → юнит-тесты → типы скриптов → DB-тесты
→ сборка → деплой. Любая красная проверка = деплоя нет. Push в `main` деплоит сам — не запускайте
параллельно `deploy:rsync` (смешает сборки). Коммит только с документацией — с `[skip ci]`.

## 3. Код

- **Линтер:** `eslint.config.mjs` (next/core-web-vitals + jsx-a11y). Ошибок быть не должно. Подавлять правило —
  только адресно (`eslint-disable-next-line <правило>`) и с комментарием «почему» рядом.
- **Форматирование:** Prettier (`.prettierrc.json`: одинарные кавычки, 120 символов, `trailingComma: es5`) и
  `.editorconfig`. Весь код разом **не** переформатируем — `npm run format:changed` форматирует только то, что
  вы меняли (незакоммиченное и коммиты ветки сверх `origin/main`). Так стиль выравнивается без шумного диффа.
- **TypeScript:** строгий режим, без `any` там, где тип известен. Типы скриптов проверяет `typecheck:scripts`.
- **Тесты:** новая логика в `lib/` — с юнит-тестом в `tests/unit/`; логика с БД — в `tests/db/`. Регрессию
  закрепляем тестом с датой инцидента в описании (пример — `tests/unit/server-health.test.ts`).
- **Регулярки с кириллицей:** `\b` не работает — границы через `\p{L}` с флагом `u`.
- **Даты контента** (lastmod, uploadDate) — по Москве с сервера, не «сегодня» машины разработчика.

## 4. Скрипты

- Одна плоская папка `scripts/` — **намеренно**: сервер вызывает их по путям `/opt/ALETHEIA/scripts/<имя>`.
  Не переносите и не переименовывайте скрипт, не проверив `/etc/cron.d/aletheia-*`, `infra/systemd/`, CI.
- Префикс по назначению (`prod-`, `setup-`, `mail-`, `telegram-`, `seo-` …) и комментарий в первых строках:
  что делает, как запускать, что меняет.
- Разовый скрипт (миграция данных, починка одного инцидента) после использования удаляйте — он останется
  в истории git. Не оставляйте `_tmp-*`.
- Крон на сервере: новые записи — в установщик `scripts/install-aletheia-http-cron.sh` (он перезаписывает файл
  целиком). Интервалы heartbeat — синхронно в `lib/cron-heartbeat.ts` и `scripts/cron-heartbeat-watchdog.sh`.

## 5. Документация

- После значимой работы: запись в [Diary.md](Diary.md) (новые сверху) и в `CHANGELOG.md` → `[Unreleased]`.
- Задачи — в [Tasktracker.md](Tasktracker.md); выполненное отмечайте там же.
- Завершённый план модуля, датированный аудит или отчёт переносите в `docs/archive/` (`git mv`) и правьте
  ссылки. Новый живой документ — добавьте строку в [docs/README.md](README.md).
- Правите статическую страницу сайта — обновите дату в `CONTENT_REVISED` (`lib/seo/sitemap-entries.ts`).

## 6. Git

- **Коммиты:** `type(scope): описание` на русском, с содержательным телом (что и **почему**).
  Типы: `feat`, `fix`, `refactor`, `docs`, `test`, `build`, `ci`, `ops`, `chore`.
- **Ветки:** короткоживущие; после слияния в `main` удаляются (локально и на GitHub).
- Историю `main` не переписываем (force-push сломает CI и клоны).
