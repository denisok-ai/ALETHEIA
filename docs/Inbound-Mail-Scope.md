# Входящая почта (IMAP): границы модуля

Цель раздела — не смешивать **оперативные коммуникации сайта**, **маркетинговые рассылки** и **чтение реального почтового ящика**.

В админке всё это сведено в раздел **«Почта»** (`/portal/admin/mail`, вкладка «Входящие» для этого документа).

## Три разных потока

| Модуль в админке | Что это | Транспорт / данные |
|------------------|---------|---------------------|
| **Коммуникации** | Разовые или по шаблону сообщения пользователям (email / Telegram). Оперативная работа менеджера. | Исходящая почта сайта: **Resend или SMTP из «Настроек»** (`lib/email.ts` → `lib/email-service.ts`). Журнал `CommsSend` + общий `EmailDeliveryLog`. |
| **Рассылки** | Запланированные кампании, большие списки, отписки. | То же глобальное отправление + `Mailing` / `MailingLog` + `EmailDeliveryLog`. |
| **Входящие** | Импорт писем из подключённого **IMAP**-ящика в БД (`InboundMessage`), просмотр, привязка отправителя к пользователю. | Чтение — **IMAP** (`lib/inmail-sync`). Ответ из интерфейса — **SMTP этого же ящика** (`lib/inmail-smtp`), **не** Resend. |

## Ответ на письмо ≠ общая исходящая почта

- Письма с сайта (регистрация, тикеты, оплата, коммуникации) идут через **единый слой** `sendTransactionalEmail` и провайдера из настроек портала.
- Когда админ отвечает из экрана «Входящие», отправка идёт с **адреса и SMTP-параметров конкретного ящика**, чтобы цепочка «вопрос–ответ» выглядела как переписка в почтовом клиенте.

Используйте **пароль приложения** Яндекс / Mail.ru / Gmail, не основной пароль аккаунта.

## Данные и безопасность

- Пароль IMAP хранится зашифрованным (`lib/encrypt.ts`, ключ — `NEXTAUTH_SECRET`).
- HTML входящих писем **санитизируется** перед сохранением (`sanitizeInboundHtml` в `lib/inmail-sync.ts`).
- Общий журнал исходящих (`EmailDeliveryLog`) хранит **метаданные** (модуль, получатель, тема, статус), без тела письма.

## Синхронизация и эксплуатация

- Ручная кнопка «Синхронизировать» вызывает API ящика.
- Фоново: **`GET /api/cron/inmail-sync`** с заголовком `Authorization: Bearer <CRON_SECRET>` — см. `docs/Env-Config.md`.
- У ящика в БД есть **`lastSyncedAt`**, **`lastSyncStatus`**, **`lastSyncError`**, **`lastSyncCheckedAt`** — по ним видно, когда последний раз синхронизация прошла успешно или упала с ошибкой (например неверный пароль).
- Первый импорт ограничен последними UID (окно в коде `FIRST_SYNC_UID_WINDOW`), за один запуск обрабатывается не более **`MAX_MESSAGES_PER_RUN`** сообщений — см. константы в `lib/inmail-sync.ts`.

## Связь с тикетами и CRM

- Входящие IMAP **не** создают тикеты автоматически (безопаснее так настроить политику вручную).
- Карточка пользователя и CRM-лид могут показывать цепочку коммуникаций по **`EmailDeliveryLog`** и входящим с совпадением email — см. раздел про почтовую историю в общей документации поддержки.
