# Чеклист аудита VPS перед автономной почтой @avaterra.pro

Выполните на **production VPS** (или заранее на тестовом сервере с тем же провайдером). Зафиксируйте результаты в тикете или в [Production-Server.md](Production-Server.md).

## 1. Сеть и порты

| Порт | Назначение | Действие |
|------|------------|----------|
| 25 | SMTP приём от других MTA (MX) | Убедиться, что **входящий** не заблокирован файрволом; у многих VPS исходящий 25 заблокирован по умолчанию — без разблокировки исходящая доставка может не работать. |
| 465 | SMTPS | Открыть если используете клиенты на SSL. |
| 587 | SMTP submission (STARTTLS) | Обычно основной порт для отправки из клиентов/MUA. |
| 993 | IMAPS | Для входящих в приложении и почтовых клиентов. |
| 995 | POP3s | Опционально, если включите POP в стеке. |

Локально можно использовать скрипт из репозитория: [`infra/mail/check-mail-ports.sh`](../infra/mail/check-mail-ports.sh) (на сервере или с вашего ПК при доступности хоста).

## 2. PTR / rDNS

Для доставки без спама желательно, чтобы IP VPS имел **обратную запись (PTR)**, согласованную с именем HELO/EHLO почтового сервера (например `mail.avaterra.pro`). Запись выставляется у **хостинг-провайдера**, не в DNS зоны домена.

Проверка (пример):

```bash
dig -x 95.181.224.70 +short
```

## 3. Ресурсы

Mailcow/Mailu рекомендует минимум **2 GB RAM**, лучше **4 GB** под продакшен с антиспамом и несколькими ящиками. Диск: учёт запаса под почтовые ящики и логи Docker.

## 4. Конфликт с nginx на 80/443

Если сайт уже занимает `443`, админку Mailcow размещают на отдельном поддомене или другом порту — см. [Mail-Server.md](Mail-Server.md).

## 5. Политика провайдера

Уточните в поддержке VPS:

- Разрешена ли **исходящая** почта на порт 25.
- Есть ли ограничения на массовую рассылку (обычно запрещена без отдельного продукта).
