# social-media-skills и ведение соцсетей школы

Дата: 2026-10-16. Вопрос: что полезного для ведения соцсетей AVATERRA (avaterra.pro), Magic Master (magicmaster.pro) и echoteka.ai дают скилы из репозитория `charlie947/social-media-skills`, и что из этого нужно школе сейчас.
Связано с: [audience-platforms-2026-10.md](audience-platforms-2026-10.md) (ставка VK + MAX + Дзен), [Plan-SEO-Social-2026-10.md](../Plan-SEO-Social-2026-10.md) (этапы 3–5).
Результат в коде: скилы `.claude/skills/avaterra-*` (8 штук, включая чек-лист правил) и тест `tests/unit/skills-lint.test.ts`.

## 1. Репозиторий и лицензия

- **Что это:** `charlie947/social-media-skills`, версия 1.1.0 от 15.09.2026 (`VERSIONS.md`). 17 публичных скилов в `skills/<имя>/SKILL.md` для Codex и Claude. Автор — Charlie Hills, рассылка MarTech AI.
- **Ориентация:** LinkedIn (посты, профиль, аналитика экспорта LinkedIn), Instagram Reels, YouTube (миниатюры), Gemini (промпты для картинок и карусели). Часть скилов требует Apify для скрейпинга постов и видео.
- **Лицензия:** MIT, «Copyright (c) 2026 Charlie Hills» (файл `LICENSE`). Адаптация и копирование разрешены при сохранении уведомления об авторском праве и текста лицензии.
- **Что сделано с лицензией:** тексты скилов написаны заново, по-русски, под школу и наш код. Фрагменты исходных SKILL.md не копировались. Идеи взяты из репозитория и отмечены в таблице ниже. Если позже появятся прямые цитаты, в файл нужно добавить уведомление MIT и строку «адаптировано из charlie947/social-media-skills».
- **Правило самого репозитория, которое мы приняли:** не собирать комментарии и ответы ни на одной площадке (`post-scorer`, `niche-research`). Для школы это совпадает с требованием не хранить ПДн.
- **Безопасность:** в репозитории есть `validate-skills.sh` и `tests/test-codex-portability.py`. Их не запускали и не исполняли. Тесты в нашем репо свои: `tests/unit/skills-lint.test.ts`.

## 4. Рекомендации по трём сайтам

### AVATERRA (этот репозиторий)

1. **Тексты для VK и Дзена сейчас** — `avaterra-post-writer` + `avaterra-headline-variants`. Сообщества VK ещё нет (решение владельца), поэтому тексты пока для ручной публикации и кросспоста.
2. **Чек-лист правил перед каждым текстом** — `avaterra-school-rules`. Он объединяет блокировки из `quality-gates.ts` с правилами, которых код не проверяет: цены, призыв купить до запуска практикума, медицинские формулировки без явного маркера, «не» в заголовках вне подписи (`titleProblems` проверяет только подпись соцсети).
3. **Очередь на 2–4 недели** — `avaterra-content-plan`. Выход — `queue.json` для `scripts/social-enqueue.ts`, который уже проверяет подписи. Ограничение: очередь принимает только видео (`file` обязателен), текстовые посты пока ведём таблицей.
4. **Ролики 30–60 с для VK Клипов и Telegram** — `avaterra-video-script`. Сценарии и приватные материалы — в `~/projects/AVATERRA-private/`, не в репозитории.
5. **Разбор переходов по меткам** — `avaterra-social-analytics`, через 4 недели. Раньше данных мало: в журнале переходов нет уникальных посетителей (`ipHash` не пишется).

### Magic Master (magicmaster.pro, только чтение)

- Переносимы **скелеты** скилов, не тексты: порядок «материал → подпись → проверка → очередь», отказ от скрейпинга комментариев, правило «не считать метрику, которой нет».
- Мастеринг — аудио, поэтому `avaterra-video-script` и `avaterra-headline-variants` не переносить. Нужен аналог `avaterra-school-rules` для MM. По плану, брендовые правила лежат в `backend/app/social/brand.py` (в этой задаче открыт только список файлов директории, сам файл не читали).
- Идея оценки «engagement = реакции + 3 × комментарии» из `post-scorer` — не брать: для нас это тоже сбор комментариев. Для MM использовать только агрегаты, которые площадка отдаёт без чтения комментариев.
- Изменений в MM не вносили.

### echoteka.ai (ООО «ЭХОТЕКА»)

- Локально не найден: в `~/projects` нет каталога с этим сайтом. `EchoReg` поиском по «echoteka» не нашёлся. Рекомендаций по коду не даём.
- Общее правило для любого сайта владельца: правила бренда в одном файле, чек-лист перед публикацией, метки `?ref=` по площадкам, аналитика по меткам.

### Пробелы в коде (в эту задачу не входят, нужна отдельная задача)

1. **Переходы из соцсетей не видны в недельном дайджесте.** Дайджест считает продажи по `acqRef`, но не читает `SocialLinkEvent` (проверено: `lib/seo/weekly-digest.ts` не обращается к модели). Добавить блок «переходы по меткам» в дайджест.
2. **Очередь не принимает текстовые посты.** `scripts/social-enqueue.ts` требует `file`, хотя планировщик умеет `publishText`. Сделать `file` необязательным для текстовых сетей.
3. **Уникальные посетители по меткам не считаются:** `SocialLinkEvent.ipHash` не заполняется по решению о ПДн. Решение нужно принять отдельно (соль, срок хранения).
4. **Коннектора VK нет.** В `lib/social/connectors/` есть `telegram.ts` и `max.ts` (с вспомогательными файлами), VK публикуется вручную.
5. **Проверка видео (ffprobe)** — пункт T3.7 плана, в `lib/social/` её не нашли.

## 6. Что не подходит и почему

- **LinkedIn, X, Instagram-реклама:** не наши площадки. Правила из репозитория про LinkedIn-формат (до 300 слов, «без тире») не переносим.
- **Реклама и посевы в Telegram и YouTube:** по `audience-platforms-2026-10.md` — правовой риск (ФАС, оговорки до конца 2026). Скилы не подсказывают покупку рекламы в этих сетях.
- **Скрейпинг чужих постов и комментариев, Apify:** не используем. Это противоречит правилу школы о ПДн и принципу «публичного репозитория».
- **Gemini для картинок и видео:** не подключаем без решения владельца; внешние сервисы с платными API — отдельное решение.
