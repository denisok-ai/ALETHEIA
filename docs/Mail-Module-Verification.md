# Проверка почтового модуля (ручной чеклист)

Используйте после изменений в `lib/email.ts`, `lib/email-service.ts`, IMAP или настройках SMTP/Resend.

## Автоматическая смесь проверок (локально)

```bash
npm run verify:mail-module
```

Скрипт проверяет базовые инварианты (например санитизацию HTML входящих). Полная проверка доставки требует живых ключей и сети.

## Исходящая почта

1. **Настройки → тест email** — ожидается успех или понятная ошибка в ответе API; запись в `EmailDeliveryLog` (`module=settings`).
2. **Регистрация** — письмо подтверждения (`module=auth`).
3. **Сброс пароля** — письмо со ссылкой (`module=auth`).
4. **Контактная форма** — создаётся лид даже при выключенной почте; при включенной — два исходящих (`module=contact`).
5. **Тикет** — уведомления пользователю и админу (`module=tickets`).
6. **Коммуникации** — тестовая отправка; ошибка провайдера видна в журнале коммуникаций и в `EmailDeliveryLog`.
7. **Рассылка** — ручной запуск / cron `mailings-send` (`module=mailings`).
8. **Оплата / PayKeeper** — при настроенных письмах по заказу — записи с `module=payments`.

## Cron

Подставьте свой URL и секрет:

```bash
curl -sS -H "Authorization: Bearer $CRON_SECRET" "https://ваш-домен/api/cron/mailings-send"
curl -sS -H "Authorization: Bearer $CRON_SECRET" "https://ваш-домен/api/cron/inmail-sync"
```

Ожидается **401** без секрета, **200** с верным секретом и JSON-отчётом.

## Входящие IMAP

1. Неверный пароль — после синка в карточке ящика видно **`lastSyncStatus=error`** и текст **`lastSyncError`**.
2. Успешный синк — новые строки в списке писем, **`lastSyncedAt`** обновляется.
3. Открытие HTML письма — контент без исполняемого JS (санитизация).
4. **Ответ** из диалога — уходит через SMTP ящика (не через Resend); при ошибке SMTP — сообщение в UI/API.

## Интеграция с пользователем и CRM

1. Карточка пользователя (**админ**) — блок почтовой истории: исходящие из `EmailDeliveryLog` по пользователю + входящие IMAP с **`matchedUserId`**.
2. Лид с email — в карточке лида видны записи `EmailDeliveryLog` по совпадению адреса.

## Отключённый провайдер

Временно уберите `RESEND_API_KEY` / отключите SMTP: критичные сценарии (контактная форма, создание лида) **не должны падать 500** только из‑за почты — см. обработку в `sendTransactionalEmail` и маршрутах.

## Автономный почтовый стек (Mailcow на VPS)

1. **DNS:** MX, SPF, DKIM, DMARC по [Mail-DNS-avaterra.pro.md](Mail-DNS-avaterra.pro.md); PTR по [Mail-VPS-Audit-Checklist.md](Mail-VPS-Audit-Checklist.md).
2. **Порталы:** раздел **Ящики домена** — создать тестовый ящик; сохранить одноразово показанный пароль.
3. **Входящие:** `/portal/admin/inmail` — ручная «Синхронизировать» или cron `GET /api/cron/inmail-sync`.
4. **Транзакционная почта без SMTP в админке:** задайте `MAIL_SMTP_HOST`, `MAIL_SMTP_USER`, `MAIL_SMTP_PASSWORD` на сервере ([Mail-Server.md](Mail-Server.md)); проверьте «Настройки → тест email».
5. Письма во внешние ящики (Gmail и др.) — проверьте попадание не в спам после прогрева IP.
