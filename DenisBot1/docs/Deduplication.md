# Avaterra Bot - Антидубли контента

## 1. Цель
Не допускать публикации постов, у которых текст или ключевая идея уже выходили
в канал. Полные дубли запрещены, близкие переформулировки - тоже.

## 2. Подход (многоуровневый)
1. **Лексический уровень** - MinHash по шинглам слов:
   - нормализация (lower, удаление URL, пунктуации, стоп-слов);
   - шинглы 3 слов (компромисс между точностью и чувствительностью к мелким правкам);
   - 128-перестановочный MinHash;
   - сравнение через Jaccard.
2. **Семантический-light уровень** - ключевые слова:
   - топ-25 частотных значимых токенов;
   - сравнение через Jaccard множеств.
3. **Жесткий уровень** - SHA-256 по нормализованному тексту:
   - блокирует абсолютные дубли по уникальному ключу
     `(project_id, text_sha256)` в `content_fingerprints`.

## 3. Пороги (по умолчанию)
- `DEDUP_JACCARD_THRESHOLD = 0.55`
- `DEDUP_KEYWORD_OVERLAP_THRESHOLD = 0.7`
- `DEDUP_LOOKBACK_POSTS = 60` (сколько последних постов сравниваем).

При превышении любого порога пост признается дублем и регенерируется.

## 4. Хранение
Таблица `content_fingerprints`:
- `minhash` (BYTEA) - сериализованная сигнатура.
- `keywords` (TEXT[]) - множество ключевых слов.
- `text_sha256` - точный отпечаток.
- `normalized_length` - длина в токенах для контекста.
- индексы: `(project_id, created_at DESC)`, GIN по `keywords`.

В `content_items` добавлены:
- `dedup_status`: `pending | passed | rejected`.
- `dedup_reason`: причина отклонения (`minhash_similarity`, `keyword_overlap`).
- `dedup_match_id`: id найденного похожего поста.

## 5. Алгоритм проверки
1. Сгенерировать кандидата текста.
2. Построить `PostFingerprint` (MinHash + ключевые слова).
3. Проверить точный SHA-256 по `content_fingerprints` - при совпадении сразу отклонить.
4. Загрузить последние `DEDUP_LOOKBACK_POSTS` для проекта.
5. Прогнать `DuplicateChecker.check()`.
6. Если `is_duplicate=True`: пометить пост как `rejected`, отправить в очередь регенерации.
7. Если `False`: сохранить fingerprint и допустить к публикации.

## 6. Производительность
- Сравнение MinHash: O(N) по последним N постам (60 - дешево).
- Для масштабирования возможен переход на LSH-индекс (`MinHashLSH`) - поиск
  ближайших за сублинейное время.

## 7. Возможные расширения
- Семантические эмбеддинги (DeepSeek embeddings или sentence-transformers)
  для повышения точности при перефразах.
- Привязка тем к контролируемому словарю с историей частот по неделям.
- Учет периода ротации тем: блокировка темы на N дней.
