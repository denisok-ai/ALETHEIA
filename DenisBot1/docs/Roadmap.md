# Avaterra Bot - Delivery Roadmap

## 1. Общая стратегия
- Итеративная поставка ценности: от безопасного каркаса к автопостингу и аналитике.
- Каждый спринт завершается демонстрацией, ретро и обновлением документации.
- Критически важные требования (секреты, идемпотентность, стабильность) делаются до масштабирования функционала.

## 2. План спринтов

## Спринт 0 (1 неделя) - Foundation и безопасность
### Scope
- Конфигурация проекта, инфраструктурный каркас, env-политика.
- База данных (скелет схемы), Redis, хранилище медиа.
- Стандартизированные логи, health-check, базовые алерты.

### Definition of Done
- Все секреты в env/secret storage.
- Поднято окружение dev/staging через Docker.
- Подключены базовые таблицы и миграции.
- Есть smoke-test запуска бота и воркера.

## Спринт 1 (1-2 недели) - Core MVP
### Scope
- Онбординг проекта в Telegram-меню.
- Анализ сайта и сохранение исходников.
- Недельный контент-план Пн/Ср/Пт.
- Генерация текста и изображений в черновики.

### Definition of Done
- Бот принимает все обязательные параметры проекта.
- Формируется план на 7 дней из 3 постов без дублей тем.
- Для каждого поста есть текст + изображение + статус.
- Ошибки интеграций логируются и видны админу.

## Спринт 2 (1 неделя) - Публикация и расписание
### Scope
- Отложенная публикация по timezone.
- Автопостинг в целевой канал.
- Retry, backoff, идемпотентность.

### Definition of Done
- Посты публикуются по расписанию с допустимым сдвигом.
- Дубли публикаций блокируются.
- При падении API запускаются ретраи и уведомление админа.

## Спринт 3 (1 неделя) - Воронка и аналитика
### Scope
- CTA сценарии и квалификация лидов (`/start` + inline-кнопки `info / warm / hot`).
- Сохранение событий воронки в `lead_events` с сегментом и контактами.
- Уведомления админам о горячих лидах и о фактах публикации.
- Сбор статистики постов (ручной ввод `/stat`) и недельный отчет (`/stats`, `/stats_full`).

### Definition of Done
- [x] CTA ведет в рабочий сценарий диалога; для каждой ветки есть свой ответ.
- [x] Горячие лиды (`warm`/`hot`) и free-form ответы пересылаются администратору вместе со ссылкой `tg://user?id=...`.
- [x] Доступен отчет по охвату, реакции, CTR и сегментам воронки за 7 дней.
- [x] После публикации админу приходит подсказка `/stat <id> ...` для ввода метрик.
- [x] Боевые DeepSeek + KIE Flux Kontext подключены, `ENABLE_AUTO_PUBLISH=true`.

### Открытое (вынесено в Спринт 4)
- Авто-сбор views/reactions через MTProto (Telethon-аккаунт).
- Бэкап картинок KIE в S3 (срок жизни оригиналов 14 дней).
- Фильтр текста на одиночные не-русские слова (борьба с галлюцинациями типа "maybe").

## Спринт 4 (1 неделя) - Brand DNA, Quality Gates и 7-дневный ритм
### Scope
- Knowledge Base AVATERRA в `knowledge/avaterra.yaml` (audiences, products, author, rubrics, cta_library, prohibited_phrases, safe_replacements, disclaimer, theme_bank).
- Расширение `brand_profiles` 12 JSONB-полями + `kb_version`; команды `/kb_load`, `/kb_show`.
- 7 типов постов под каждый день недели (educational/pain/practice/author/faq/course/reflection).
- 7 шаблонов промптов с явной структурой, аудиторией, CTA из YAML и дисклеймером по триггерам.
- Quality gates: prohibited_phrases, latin_word, length_window, cta_present, disclaimer_required + до 2 повторов с фидбеком.
- Бэкап картинок KIE: S3 (boto3) или локальный диск (`/app/runtime/images`); публикатор использует backup.

### Definition of Done
- [x] `knowledge/avaterra.yaml` загружается на старте бота и применяется к `brand_profiles` (kb_version фиксируется).
- [x] План недели формируется на 7 дней с разными post_type под каждый weekday.
- [x] Тексты, не проходящие quality gates, перегенерируются до 2 раз; финальный отказ помечается `quality_failed`.
- [x] Картинки KIE задублированы в backup-сторадж и публикуются из него.
- [x] Все 58 unit-тестов проходят локально.
- [x] Боевая выкатка: миграции 009 и 010, KB загружена, smoke `/plan_now` и DeepSeek-генерации зелёный.

### Открытое (перенесено в Спринт 5)
- Ранжирование тем по post_statistics, A/B варианты CTA и заголовков.
- Расширение theme_bank в YAML до 60+ тем (особенно practice/reflection).
- Потенциальный pre-signed S3 URL вместо file:// при включении S3-credentials.

## Спринт 5 (1-2 недели) - Site Radar + админ-операции в Telegram
Спринт идёт двумя дорожками. Если объём не влезает в 1-2 недели, дорожка B выносится в Спринт 5.1 без потери ценности.

### Дорожка A - Site Radar (DoD из roadmap)
#### Scope
- Стабилизировать обход и логирование `integration_logs` для радара.
- Метрика "доли noise" в логах (счётчики high/medium/low/noise).
- High-сигналы автоматически попадают в `theme_pool` с `source='radar'`, без дублей с `source='kb'`.
- Уведомления админу: только Telegram, краткий формат.
- Команда аудита сигналов: `/radar_signals` с фильтром high/medium и пагинацией.

#### Definition of Done
- Бот раз в N часов обходит avaterra.pro и фиксирует версии.
- Шум фильтруется (доля noise-сигналов < 5% видна в логах).
- High-сигналы попадают в `theme_pool` (source='radar') и не дублируют KB-темы.
- Полный аудит сигналов доступен через Telegram-команду админа с пагинацией.

#### Acceptance Criteria
- Новый URL в sitemap создает запись в `site_pages` и high-сигнал.
- Изменение цены в карточке курса генерирует sales/course-идею.
- Новая статья блога создает educational-идею с темой и тезисами.
- Шумовые баннеры и таймеры не порождают сигналов.

### Дорожка B - Telegram Admin Console
#### Scope
- Команда `/admin` - главное меню с inline-кнопками: "План недели", "Очередь качества", "Радар", "Статистика", "Авто-публикация on/off".
- "План недели": 7 дней с типами, темами и статусами; callback на превью поста.
- "Очередь качества": список `quality_failed` items с действиями "перегенерировать", "открыть текст", "пропустить".
- Действие "перегенерировать" сбрасывает item в `draft` и триггерит `prepare_item` (учёт лимитов retry).
- Превью поста показывает кодами quality gates последней попытки (из `prompts.error_code`).

#### Definition of Done
- Админ за 3-5 нажатий доходит до плана недели, очереди quality_failed и регенерации.
- Регенерация одного item не блокирует основной поллинг бота.
- Перегенерированный item корректно проходит pipeline (текст -> quality -> KIE -> backup).
- Все callbacks ограничены админами (через `AdminOnlyMiddleware`).

### Что вне скоупа
- Веб-админка, CRM, BI.
- MTProto/Telethon-сборщик статистики.
- A/B заголовков и ранжирование тем по `post_statistics` (нужно 2-4 недели данных, выносится в Спринт 6).

## 3. Критерии приемки MVP (финальные)
- Проект онбордится через Telegram.
- Сайт анализируется и структура данных сохраняется.
- Еженедельно создается и исполняется контент-план 3 поста/неделя.
- Тексты и изображения генерируются автоматически.
- Публикация в канал стабильна и без дублей.
- Работает базовая воронка продаж по CTA.
- Система собирает статистику постов.
- Админ получает уведомления о сбоях.

## 4. Риски сроков и смягчение
- Задержки из-за внешних API -> мок-адаптеры + fallback шаблоны.
- Нестабильность расписания -> отдельный worker и queue monitor.
- Просадка качества контента -> quality gates + ручной override в Telegram.
